# 声音克隆落地报告

## 结论先说

**XTTS v2 已在本机跑通，音色克隆可用；但 CPU 推理 RTF≈2.1，不能直接用于直播实时合成。**

必须配「预生成 + 队列播放」架构（见第 4 节），才能既保留克隆音色、又不卡顿。

## 2. 踩过的四个坑（复现时必看）

| 现象 | 原因 | 解法 |
|---|---|---|
| `UnpicklingError: Weights only load failed` | torch≥2.6 默认 `weights_only=True`，Coqui checkpoint 含自定义类 | `torch.serialization.add_safe_globals([XttsConfig, XttsAudioConfig, XttsArgs, BaseDatasetConfig])` |
| `ImportError: cannot import BeamSearchScorer` | transformers 5.x 删除了该符号 | 降到 `>=4.33,<4.42` |
| `TorchCodec is required` | torchaudio≥2.9 改用 torchcodec 读音频 | 降到 torchaudio 2.4.1（**不要装 torchcodec**） |
| `libtorchcodec_core4.dll` 加载失败 | torchcodec 与 torch 版本不匹配 | 同卸载 torchcodec |
| DirectML 加速失败 | `Cannot set version_counter for inference tensor` | XTTS 与 DirectML 不兼容，**放弃 GPU 路线** |

## 3. 实测速度（决定架构的关键数据）

```
模型加载        12~13 秒（一次性，可常驻避免）
短句 12 字      8.3 秒   → 音频 3.9 秒   RTF 2.11
中句 22 字     12.8 秒   → 音频 6.1 秒   RTF 2.10
```

调 `gpt_cond_len`（6→3）、拉满线程数，效果均 <5%。

**RTF 2.1 的含义**：生成 1 秒语音要 2.1 秒。弹幕一密集就必然积压。

---

## 4. 正确的架构：预生成 + 队列（原系统就是这么做的）

逆向时发现的字段不是偶然：`txtArray`（待播文本）、`audioArray`（已合成音频）、`makeAudio`（逐句预生成）、`rewriteinterv`（每 20 秒改写）。

**他们也不是实时合成。** 所以我们的架构应当：

```
弹幕进来
   ↓
话术改写（speak-script.mjs，毫秒级）
   ↓
预生成队列（后台慢慢合成，RTF 2.1 无所谓，只要平均产出 > 平均消耗）
   ↓
播报队列表（audioArray）
   ↓
播放到虚拟声卡
```

**关键指标不是单句延迟，而是「平均合成速度 vs 平均弹幕速度」**：

- 一条弹幕改写后约 20 字 → 合成 13 秒 → 音频 6 秒
- 只要**弹幕间隔 > 13 秒**就能跟上
- 弹幕密集时需要**限流 + 相似弹幕合并**（同一问题一分钟内只答一次）

这正好是 `speakMode: 'keyword'` 存在的意义：**用关键词过滤把弹幕量压到可合成的水平**。

---

## 5. 三种方案的取舍

| 方案 | 音质 | 速度 | 成本 | 建议 |
|---|---|---|---|---|
| **A. 预生成队列 + XTTS 克隆** | 高（真克隆） | RTF 2.1，靠队列缓冲 | 免费 | ⭐ 推荐，已验证可用 |
| B. 云端克隆 API（火山/MiniMax/SiliconFlow） | 高 | 快（RTF<1） | 按字符计费 | 想要低延迟选这个 |
| C. Edge TTS + 话术改写 | 中（不是本人音色） | 快（RTF 0.4） | 免费 | 现在的状态 |

**推荐组合：A 做主，C 做兜底。** 队列空时用 Edge 快速应答，队列充足时用克隆音色。

## 7. 下一步（可选）

要把克隆接进主流程，还需要：

1. **常驻推理服务**（避免每句重载模型，省 13 秒）
2. **预生成队列**（后台合成，前端按序播放）
3. **弹幕限流与合并**（相同意图 N 秒内只答一次）
4. **音色切换**：把 `hostVoice/assistantVoice` 从 Edge 音色 ID 换成参考音频路径
5. **兜底策略**：队列见底时自动降级 Edge TTS

预计工作量：中等（约 200 行）。要接就说一声。
