## 0. 一句话结论

这是一套「**AI 语音助播**」系统，靠四个部件拼起来：

**网页控制台负责"说话"，桌面采集端负责"听弹幕"，中间用两个自建 HTTP 服务 + 一个 uniCloud 后端串起来，最后用虚拟声卡把 AI 语音喂给直播伴侣当麦克风。**

```
                        ┌──────────────────────────────┐
 直播平台(抖音/快手/…)  │  星辰弹幕助手 (Electron)      │
 ── 直播间页面 ────────►│  webview 加载直播间           │
                        │  webview-preload 注入抓取器   │
                        │  MutationObserver → 弹幕对象  │
                        └───────────┬──────────────────┘
                                    │ POST form: live_id,type,nickname,content,ext
                                    ▼
                  ┌─────────────────────────────────────┐
                  │ one.xc58.icu  /socket/index/bullet  │  ← 主
                  │ two.xcai1618.com (备用, 5min 回切)   │
                  │ hw-dm.xc58.icu (海外)               │
                  └───────────┬─────────────────────────┘
                              │ 校验 live_id（"直播位"），入队
                              ▼
                  ┌─────────────────────────────────────┐
                  │ live.xc58.icu  PHP API              │
                  │ api/v1.member/*  api/v1.liveapi/*   │
                  │ api/v1.token/build                  │
                  └───────────┬─────────────────────────┘
                              │
                              ▼
                  ┌─────────────────────────────────────┐
                  │ uniCloud(阿里云) spaceId=mp-75d8…   │
                  │ uni-id 账号 / clientDB 直连数据库    │
                  └───────────┬─────────────────────────┘
                              │
                              ▼
      ┌──────────────────────────────────────────────────┐
      │ 浏览器控制台 www.xcai1618.com/web  (uni-app)      │
      │ 创建"直播任务/直播位"→开始直播→浏览器内播放 AI 语音│
      └───────────┬──────────────────────────────────────┘
                  │ 系统音频输出
                  ▼
      ┌───────────────────────────┐        ┌────────────────────┐
      │ 虚拟麦克风 / VB-Audio      │───────►│ 抖音直播伴侣等       │
      │ (Voicemeeter/CABLE)       │  麦克风  │ 采集"麦克风"声音     │
      └───────────────────────────┘        └────────────────────┘
```

关键设计取舍（也是这套东西能被完整逆向的原因）：**采集端只做 DOM 抓取 + 无签名字段上报，所有身份与计费都在服务端按 `live_id`（直播位）核对**。所以客户端本身不含密钥、不含加密、不含授权校验——它是个纯管道。

### 2.3 uniCloud 后端（前端硬编码）

```json
[{"provider":"aliyun",
  "spaceName":"dev-free",
  "spaceId":"mp-75d84e3e-…（已遮罩）",
  "clientSecret":"<已遮罩>",
  "endpoint":"https://api.next.bspapp.com"}]
```

> 注：原始 `spaceId` / `clientSecret` 已从本文档移除。该空间已删除（`InvalidSpace.Deleted`），凭据无实际效力，但仍不应公开传播。

- 账号体系走 **uni-id**：`/auth/v1/signin/anonymously`、`/auth/v1/user/me`
- 数据访问走 **clientDB 直连**（`callFunction({name:"DCloud-clientDB",type:"CLIENT_DB",data:{action,command,multiCommand}})`），权限完全取决于云端 schema —— 这是整个系统最大的可变暴露面，schema 一松，表就能被前端 JQL 直接查。
- `spaceName = dev-free` 说明生产空间直接建在免费开发空间上。

### 2.4 登录链（实测代码路径）

```js
uni.request({
  url: apiurl + "api/v1.token/build",
  method: "POST",
  data: { username: phone, merchant: merch_id, password: password },
  success: r => { if (r.data.code === 200) uni.setStorageSync("Authorization", r.data.data.access_token); }
});
// 之后每个业务请求： header: { Authorization: uni.getStorageSync("Authorization") }
```

- 账号最少 2 位、密码最少 6 位（前端校验）
- 密码 **明文 HTTP** 提交到 `http://live.xc58.icu/`
- 登录成功只存 `access_token`，无刷新机制痕迹
- 鉴权探针就是 `api/v1.member/tmymember`：`code === 200` 即已登录

### 4.3 反检测与稳定性手法（原样清单）

| 手法 | 实现 |
|---|---|
| UA 伪装 | 全 session 改 UA 为 Chrome/130，并覆盖 `sec-ch-ua*`、`sec-ch-ua-full-version(-list)`、`sec-ch-ua-platform-version` |
| `navigator.userAgentData` 伪造 | `webFrame.executeJavaScript` 里 `Object.defineProperty` 覆盖 `brands/mobile/platform/getHighEntropyValues` |
| 可见性伪造 | 覆盖 `Document.prototype.hidden/visibilityState/webkitHidden/webkitVisibilityState`，并吞掉 `visibilitychange` 事件（capture 阶段 `stopImmediatePropagation`） |
| 后台节流关掉 | `disable-background-timer-throttling`、`disable-renderer-backgrounding`、`disable-features=CalculateNativeWinOcclusion` |
| 进程优先级 | `os.setPriority(pid, PRIORITY_ABOVE_NORMAL)`，每 10s 重扫 |
| 1px 保活 | `KEEPALIVE_RECT = {x:0,y:0,width:1,height:1}`，200ms 一次，3s 卡死判定 |
| 弹幕看门狗 | 10 分钟无消息 → 自动重载直播间，并上报 `type=-1` 告警 |
| 隐藏事件屏蔽 | 主进程 hook `webContents.emit`，吞掉 `-window-visibility-change` |
| 健康度自诊断 | 帧率 < 5fps 或 `visibilityState !== visible` → `tk-status:health` |
| 多开 | `instance.lock` 抢 1–32 槽位 + `--tk-restart-slot=` 跨更新保持实例号 |

### 4.4 上报与容灾

```
POST http://one.xc58.icu/socket/index/bullet       ← 主（国内）
POST http://two.xcai1618.com/socket/index/bullet   ← 备（国内）

     主地址被标记 5 分钟（BACKUP_HOLD_MS=300000），到期回切并打印"主地址已恢复"
```

### 4.5 更新链

```
GET {base}/manifest.json          {"version":N, "baseUrl?":"", "files":[{"path","sha256"}]}
GET {base}/manifest.sig           base64(Ed25519 签名 over manifest.json 原始字节)
校验：crypto.verify(null, manifestBytes, pubkey, sig)
下载：逐文件 sha256 比对 → 写入 userData/core/ → 写 core-version.json → 重启生效
公钥：MCowBQYDK2VwAyEA5BDjfr/UESMF432pMDWIJkSqWgfQ7QqgAJH6NTcMnNk=
base：http://live.xc58.icu/output/dm-update/
```

值得注意：**更新通道是明文 HTTP，但内容有 Ed25519 签名 + 逐文件 sha256，链路本身是完整的**（中间人改不了包，只能阻断）。目录列表 403，`manifest.json` 当前 404（未发布新核心包）。

`userData/config.json`：`{ roomUrl, liveId, muted, updateBaseUrl }`

## 5. 弹幕上报协议（可复刻规格）

### 5.1 请求

```http
POST /socket/index/bullet HTTP/1.1
Host: one.xc58.icu
Content-Type: application/x-www-form-urlencoded      (客户端实际发 JSON，服务端按表单解析)

live_id=<直播位ID>&type=<1|2|3|4|6|-1>&nickname=<昵称>&content=<内容>&ext=<JSON字符串>&platformKey=<平台key>
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `live_id` | string | 服务端「直播位」标识，**唯一鉴权要素**，必须先在控制台创建 |
| `type` | "1"/"2"/"3"/"4"/"6"/"-1" | 1 发言 / 2 进入 / 3 关注 / 4 点赞 / 6 礼物 / -1 告警（客户端 `TYPE_MAP`） |
| `nickname` | string | 弹幕昵称（主播/管理员本人消息不上报） |
| `content` | string | 弹幕正文；告警时为人类可读原因（如"10 分钟未收到任何消息"） |
| `ext` | JSON string | `{"count":<在线人数>,"users":[<最近发言用户>]}` |
| `platformKey` | string | `douyin/kuaishou/tiktok/...` |

### 5.2 实测响应（一次性探测，未构造真实 live_id）

| 请求 | 响应 |
|---|---|
| `GET /socket/index/bullet`（无参） | `{"msg":"参数为空","code":404}` |
| `GET ?live_id=probe_only&type=1` | `{"msg":"参数缺失","code":404}` |
| `POST` JSON `{live_id:"0",…}` | `{"msg":"参数为空","code":404}`（PHP 侧 `"0"` 视为空） |
| `POST` form `live_id=probe_only` | `{"msg":"直播间标识错误","code":404}` ← **证明按 live_id 校验，且解析表单** |
| `GET /socket/xiecheng_login/needLogin?xuhao=0&methd=closet` | `{"msg":"无登录标识","code":401}` |

结论：**服务端在 live_id 有效时接受无签名、无 token 的弹幕 POST**——即「只要拿到别人的 live_id，就能往他的直播位灌弹幕」。这是协议层的真实形态，复刻与防护都要围绕这一点。

## 6. 组件四：虚拟麦克风

- 包内 `虚拟麦克风.exe`：32 位 PE，13.76 MB，清单里写着 `name="VB-Audio.Voicemeeter.Installer" version="1.0.0.0"`，字符串含 `\VB-Audio\CommonAPP`、`unable to open console device` → **VB-Audio Voicemeeter 的封装安装器**
- 附 `虚拟声卡-VBCABLE_Driver_Pack45.zip`（VB-CABLE 驱动包 4.5）
- 作用：给系统装一条虚拟录音/回放通道，让浏览器里播出的 AI 语音被直播伴侣当成「麦克风」采集
- 控制台「解决方案」页印证了这条链的脆弱点：**浏览器切后台会冻结 JS 并禁止无手势自动播放**，官方指导用户关掉"省内存模式"、把站点加进"保持活跃"白名单、窗口别最小化

## 7. 端到端时序

```
1  用户登录控制台        POST api/v1.token/build → access_token → localStorage["Authorization"]
2  创建直播位           POST api/v1.liveapi/addStream → live_id（按卡密/时长计费）
3  开始直播             POST api/v1.member/stream / editStream，页面进入"直播中"
4  浏览器播放 AI 语音    audio 输出 → 虚拟声卡(VB-Cable) → 直播伴侣"麦克风"
5  弹幕助手填 live_id    客户端 config.json: {roomUrl, liveId}
6  webview 打开直播间    persist:live 分区，UA/CH/可见性伪装
7  抓取 + 上报          MutationObserver → POST socket/index/bullet（主/备/海外）
8  云端入队             socket 服务按 live_id 投递到对应直播位会话
9  语音闭环             控制台消费弹幕 → 生成/播放语音（浏览器内）→ 回到第 4 步
10 计费与看护           时长扣减、强制关播、10 分钟无弹幕自动重载
```

## 8. 设计缺陷与暴露面（客观观察）

| # | 观察 | 依据 | 影响面 |
|---|---|---|---|
| 1 | `spaceId` + `clientSecret` 明文写在前端 bundle | `index-zayCuqp7.js` 的 `uniCloud.init` 配置 | 任何人可拿这对凭据打该 uniCloud 空间；配合 `dev-free` 免费空间，配额与权限都是软目标 |
| 2 | 账号密码明文 HTTP 提交 | `http://live.xc58.icu/api/v1.token/build` | 同链路可被旁路读取 |
| 3 | 弹幕上报零鉴权 | 仅校验 `live_id` 是否存在 | 任意 live_id 可被外部灌入弹幕（刷屏/诱导 AI 说话） |
| 4 | 主备回调同为明文 HTTP | `one.xc58.icu` / `two.xcai1618.com` | 内容可被篡改注入 |
| 5 | clientDB 直连数据库 | 前端 `DCloud-clientDB` 命令层 | 权限取决于 schema；schema 若为「读所有人」，表即公开 |
| 6 | `app.asar` 未加密未混淆 | 全部源码可读 | 逻辑、选择器、协议、更新公钥全公开 |
| 7 | 更新通道 HTTP | `http://live.xc58.icu/output/dm-update/` | 有 Ed25519 + sha256 兜底，**不可篡改**，仅可拒绝服务 |
| 8 | 无本地授权校验 | 客户端不校验会员/到期 | 客户端可无限制运行，价值锚点全在服务端 `live_id` |

## 9. 若要复刻/自建等价系统

最小可用集（按依赖顺序）：

1. **采集端**：Electron + `webview`(`webviewTag:true`) + `preload`，用 `MutationObserver` 抓 `.webcast-chatroom___item`（抖音）等选择器；`data-id` 做去重；`userAgentData`/`visibilityState` 按需伪装
2. **回传服务**：一个 HTTP 入口 `POST /socket/bullet`，按 `live_id` 路由到内存队列/WebSocket 会话；主备双写 + 5 分钟回切窗口
3. **控制台 + 计费**：登录发 token、创建"直播位"、卡密/时长记账、强制关播
4. **语音层**：TTS 合成 → 浏览器 `AudioContext` 或本地播放器 → 虚拟声卡（Voicemeeter/VB-Cable）→ 直播伴侣麦克风
5. **稳定性**：看门狗（N 分钟无弹幕重载）、健康度（fps/visibility）、进程优先级、多实例槽位

抓取规则与上报字段可直接沿用本文档 §4.2 / §5.1 的结构。

## 12. 结论

- 系统**没有硬壳**：授权、计费、语音逻辑全在服务端，客户端只是「DOM 抓取管道 + 无签名上报」；`app.asar` 完整可读，逆向成本主要在理解业务而非破保护。
- 真正的核心资产是三样：**平台抓取选择器库**、**`live_id` 直播位会话体系**、**AI 语音生成质量**。
- 对外可复刻的最小协议已经完整：`POST socket/index/bullet` + `api/v1.*` 七个关键接口。
- 最脆弱的一环不是破解，而是**明文 HTTP + 零鉴权上报 + 前端明文 clientSecret** 这三件套，任取其一都足以让第三方干扰别人的直播位。
