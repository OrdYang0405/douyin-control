# 声音克隆：A + C 混合方案（已交付）

## 一、听效果（三步）

服务已启动：**http://127.0.0.1:8080**（`admin` / `admin123`）

1. 登录后，左侧有一个「克隆演示」直播位，音色已设为 **ref1 · 本地克隆**
2. 右侧「试听」输入框随便写句话，点 **试听** → 会走克隆音色（新句子约 10 秒）
3. 想看「秒出」效果：先点 **预热克隆**（把常用话术提前合成），之后相同句子 **19 毫秒**返回

---

## 二、这套方案到底解决什么

| 问题 | 解法 |
|---|---|
| 本地 XTTS 太慢（RTF 2.1，一句话 10 秒） | **C 方案兜底**：先用 Edge 即时出声，克隆后台生成 |
| 克隆生成完，观众已经错过 | **克隆完成后立即推送播放**（`clone-ready` 事件） |
| 直播时听众等不了 10 秒 | **预热**：常用话术提前合成，命中即 19ms |

### 实测数据

```
预热过的句子     : 19 毫秒      ← 秒出
未预热的句子     : 9.6 秒
Edge 即时出声    : 约 1.3 秒
模型首次加载     : 16~18 秒（仅一次，之后常驻）
克隆 RTF         : 2.1（20 字 → 10.8 秒合成 → 5 秒音频）
```

## 三、架构

```
弹幕进来
   │
   ├─ 话术改写（speak-script.mjs，毫秒级）
   │
   ├─【快轨】Edge TTS ──────────────► 立即播放（1.3 秒内出声）
   │
   └─【慢轨】XTTS 克隆（后台）──┐
                                ├─ 生成完 ─► 推送 clone-ready ─► 播放真人音色
                                └─ 同时存入缓存 ─► 下次相同句子 19ms
```

**关键设计**：两条轨并行，观众永远不会「等」，同时逐步拿到真人音色。

---

## 四、怎么用

### 1. 准备音色素材

把一段 6~15 秒的清晰人声放到 **`D:\tts-refs\`**（纯英文路径，规避 Windows 中文路径问题）：

```
D:\tts-refs\
  ref1.wav      ← 你的音色样本（16k/22k Hz 单声道最佳）
  ref2.wav      ← 可以放多个，控制台会都列出来
```

> 用 mp3 的话先转 wav：
> `ffmpeg -i 素材.mp3 -ar 22050 -ac 1 D:\tts-refs\ref1.wav`

### 2. 选音色

控制台「语音规则 → 音色」下拉最上方就是 `ref1 · 本地克隆`。

### 3. 预热（重要）

```
POST /api/v1.liveapi/warmupClone
{ "id": 直播位ID, "lines": ["话术1", "话术2", ...] }
```

不传 `lines` 就用内置的 8 句直播常用话术。

**预热多少合适**：一场直播的高频话术一般 20~50 句，全部预热后基本都能秒出。

## 五、踩过的坑（复现必看）

| 现象 | 原因 | 解法 |
|---|---|---|
| `ValueError: 参考音频不存在`（文件明明在） | Windows 下 python stdio 按本地代码页解码，中文路径变乱码 | 强制 `stdin.reconfigure(encoding="utf-8")`；参考音频放 ASCII 路径 |
| 克隆静默回落到 SAPI | `speak()` 降级链吞掉了真实错误 | 直接调 `speakClone` 才看到真错误 |
| 两个 python 进程各占 4.6GB | 测试残留 + 服务进程同时跑 | 启动前清理 `Get-Process python` |
| `ImportError: BeamSearchScorer` | transformers 5.x 删除该符号 | 降到 4.41.2 |
| `TorchCodec is required` | torchaudio ≥2.9 改用 torchcodec | 降 torchaudio 到 2.4.1 |
| `UnpicklingError: Weights only load failed` | torch ≥2.6 默认 `weights_only=True` | `add_safe_globals([XttsConfig, XttsAudioConfig, XttsArgs, BaseDatasetConfig])` |
| Coqui `hash.md5` 校验总失败 | 该文件是过期数据 | 以 HuggingFace LFS SHA256 为准 |
| DirectML 加速报 `Cannot set version_counter` | XTTS 与 DirectML 不兼容 | 放弃 GPU，走 CPU |

## 六、当前限制（诚实说明）

1. **未预热的新句子要等 10 秒**——这是 CPU 推理的物理极限（RTF 2.1），无法绕过
2. **内存占用 2.8GB**（XTTS 模型常驻）
3. **参考音频质量决定克隆像不像**——噪声大、有背景音乐的素材效果差
4. **不做事先训练的精细克隆**——XTTS 是零样本克隆（给参考音频直接合成），比 GPT-SoVITS 那种训练过的略逊

## 七、如果要更进一步

| 目标 | 做法 | 代价 |
|---|---|---|
| 新句子也秒出 | 换云端流式 TTS（首字 0.5~1.5 秒） | 按量付费 |
| 更像真人 | GPT-SoVITS 用 10 分钟素材训练专属模型 | 需训练，CPU 约 1~2 小时 |
| 更多情感变化 | 参考音频准备 3~5 种情绪版本，随机切换 | 零成本 |
